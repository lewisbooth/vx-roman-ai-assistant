# Roman AI Assistant frontend

The customer React Router app uses Tailwind CSS 4 inside a Shadow DOM. Its compact **Ask Roman** launcher sits to the right of the header search bar, uses the tagline-free Roman wordmark and star, and opens a fullscreen ivory shopping experience. The header button is the only launcher; Roman has no floating controls. The storefront stays rendered behind an opaque overlay, allowing native measurement, option and pricing controls to keep working. Roman owns the visible shopping experience on desktop and mobile. The host, launcher and assistant use z-index `2147483647` to sit above theme widgets. The lazy runtime intercepts the HD theme?s specific `cart-drawer-dialog` open request while Roman is visible, preventing its native top-layer notification from covering Roman; cart updates and other dialogs remain theme-owned. Closing Roman restores the native confirmation behavior. The React instance persists across successful in-place navigation and assistant toggles. Development stores connect to Luna text chat and GPT-Live voice through the separate Roman backend, sharing one persistent transcript.

For a new session, only the small launcher script runs on page load. The header wordmark has its own tagline-free SVG; the assistant retains the full logo. The first click immediately opens the ivory shell and requests the React bundle and logo. A logo and indeterminate loading bar remain until React commits and at least one second has passed since loading began. This deliberate development delay applies once per page load, including cached loads and automatic restoration; reopening or remounting on the same page does not restart it. Slow downloads add no extra delay. Closing keeps the runtime mounted, and load failures offer an explicit retry. The home view contains the Roman by SelectBlinds logo, conversation heading, four exact Figma illustrations and a working text composer. Below 640px, the smaller logo sits at the top left and tighter spacing brings the heading and tiles higher. The welcome tiles remain available while voice connects and Roman greets the customer; the shared composer follows the current text/voice mode. The first customer speech, submitted text or tile choice switches immediately to the conversation. Tiles submit measuring, style, no-drill or visualization context and have a burgundy hover/focus border. Typed and tile replies keep voice connected; a reply submitted during connection is included in readiness so Roman answers it instead of starting the welcome. Visualization requests begin with a room photo and blind choice; uploads and generation are not implemented yet. On development stores, Settings opens voice selection and manual tools. Desktop keeps its logo and header layout with a text Settings action. Mobile uses one header row: a hamburger menu on the left, Chat/Cart/Gallery in the center and Close on the right. The menu contains the Roman logo, End chat and Settings.

Open/closed state is saved in `sessionStorage` for the current tab and storefront origin. Normal navigation or reload automatically reopens and mounts Roman when it was open, with keyboard focus contained in Roman until it closes. Back/Forward cache restores follow the latest saved state. Closing keeps subsequent pages collapsed. An active saved chat quietly loads the runtime after full navigation so it can record public page visits; visitors who have never started a chat still get only the launcher. If browser storage is unavailable, the assistant remains usable and logs one warning per page. Conversation credentials are also saved per tab once a first message starts a session. Reloads create a fresh React runtime and restore the same server transcript through Shopify's signed proxy. Closing stops voice but preserves the conversation and any active text reply; reopening refreshes its result. New confirmed product/sample additions show the shared branded modal until dismissed. Shared dialogs use a title, optional description and actions with even spacing, without a repeated logo. View Cart switches directly to Roman's Cart without sending a message; Keep Shopping queues a product/sample-specific continuation through the shared chat path, preserving voice. A sample continuation explicitly resumes where the customer left off with that blind. Enqueue failures remain visible in the modal for retry. Restored history and receipts received while Roman is closed or another approval is active do not replay the modal. The durable plain-text cart events remain in the transcript. Model navigation and manual storefront visits remain quiet context. Choose blind sends a customer message; only confirmed Roman navigation selects the active blind, retaining its durable record for selection and admin inspection without a customer notice. End chat waits for server acknowledgement, clears local credentials and returns to the home screen; the next message starts a new conversation.

`src/header-launcher.ts` attaches the isolated **Ask Roman** wordmark button immediately right of the input selected by `main-header [data-testid="menu-search-input"]`. Its Ask text uses the theme’s `DMSansSite` font face (DM Sans); Roman remains the SVG wordmark. It stays inside the search row as a separate non-submit button, matches the input height and uses the follow-up prompt's burgundy, copper and ivory animated border. The wordmark retains its 3px optical offset; an open assistant gives it a burgundy background and light content. Header replacement and responsive changes reattach the same button without moving or remounting the body-owned assistant. Closing returns focus to the available header launcher. Embed removal cleans up the button and observers.

The fullscreen shell does not scroll; the underlying document is scroll-locked while open. The transcript, product details and developer tools own their scrolling. Scrollbars are hidden within Roman while wheel, touch, keyboard and carousel dragging remain available. Large text emphasizes the current turn, previous turns remain scrollable, and Back to the conversation resumes following. The current quick-answer or measurement widget sits at the end of the Chat transcript and scrolls with it. Quick-answer choices wait for their associated text reply to finish revealing; carousels, measurement inputs and receipts appear as soon as available. Cart and Gallery do not show these controls. The active panel contains the canonical text question; retiring it leaves that question as ordinary transcript text. Measuring instructions and the established unit hint stay in the active panel rather than the transcript; field labels remain internal. Voice questions supply controls only; their recorded captions own spoken history, so answering never adds a second question bubble. Text-mode questions have a polite announcement region.

The loading bar intentionally animates regardless of the browser's reduced-motion preference.

## Develop, build and publish

Follow the [root setup](../README.md), then run commands from the repository root:

```powershell
npm run dev:frontend
```

Open http://127.0.0.1:5173. The standalone preview uses the `hd-dev-multi` profile against local demo pages without Shopify credentials or the admin server. It does not simulate Shopify pricing, product configuration or cart behavior.

```powershell
npm test
npm run build:frontend
npm run deploy
```

`npm test` runs frontend and backend behavior tests. `build:frontend` builds both extension bundles and copies the design assets; `watch:frontend` rebuilds them on changes. `deploy` checks and rebuilds before releasing through Shopify CLI; see the [root publishing instructions](../README.md#publish) for release scope and version labels. Enable **Assistant icon** in the theme's **App embeds**, save and refresh. Admin hosting is separate.

The build enforces Shopify's 10 KB limit for the initial script. Its ES2022 target preserves compact native private fields; React and theme navigation remain in the lazy runtime.

Theme-handled forms, modified clicks, external links and links marked `data-roman-native-navigation` retain native behavior and can end the current assistant instance. Ordinary same-origin links use Roman navigation while the assistant is open.

The cache belongs to this storefront runtime and clears on reload or disposal. New voice carousels appear when ready and follow the associated response's captions as they arrive. Tool completion preserves customer utterance boundaries without splitting Roman mid-sentence; hidden page observations and navigation do not split captions. Same-speaker captions tolerate pauses up to three seconds, while persisted fragments and text stay unchanged. A delayed backend delegation after customer speech does not split Roman's acknowledgement into separate bubbles; the shared server projection retains actual customer, visible-event and voice-session boundaries.

Closing the assistant stops microphone capture and playback immediately, cancels unfinished voice startup and finalizes the voice session through the existing stop API. Reopening stays in text mode until Start voice is chosen. The conversation, selected blind, cart and gallery remain saved. Text-only work continues when closed; approvals remain inside Roman for review on reopening. Failed voice finalization retains an actionable End voice retry without resuming audio. Full reloads stop the old audio connection and restore the transcript; an open Roman runtime then makes its single voice attempt, subject to browser permission and the saved text-mode preference. If an old connection is still ending, **End voice** explicitly closes it before continuing. Page exit sends a best-effort stop; 20-second heartbeats keep a 45-second transport lease alive but do not count as conversation activity. The server ends quiet voice after 60 seconds; a red chat warning appears with 15 seconds remaining and disappears when either speaker resumes or a text/quick answer is accepted. Active delegated work is allowed to finish before the idle countdown resumes; the ten-minute connection cap remains. Lost start responses are stopped using their original ID, never replayed. End chat and embed removal also stop local media.

A temporary WebRTC disconnect has ten seconds to recover on the same connection; terminal peer/channel failures stop immediately. Recovery preserves mute and never starts another model session or replays a tool. The backend classifies provider command errors: rejected optional spoken progress keeps media connected, while session closure and transport failures still stop it. Live may acknowledge typed replies and quick answers naturally. When their advisor turn takes longer than 2.5 seconds, a quiet connection receives one grounded spoken progress cue even before a store tool starts; an active tool supplies more specific wording. The verified answer queues behind it. Fresh speech supersedes old work. Live does not report exact browser playback completion, so the queue uses a bounded generated-audio quiet window. Unexpected client failures report `connection_lost` to the backend and log categorical transport states under `[Roman] Voice connection failed.`, without audio, captions or credentials. The customer timeline never matches or removes question text from captions. Voice widgets provide answer controls, while the recorded captions remain the source of spoken history.

While Roman is open on an installed storefront, the client checks `/apps/roman/availability` every ten seconds, or every three seconds during a confirmed outage. The backend can report `available`, `degraded` (the fallback model is serving replies), or `suspended`; chat requests can also signal suspension immediately with HTTP 503 and `SERVICE_UNAVAILABLE`. Suspension keeps the transcript and unsent drafts, stops local voice media and new storefront tool work, pauses queued messages, and replaces the composer with a grey **Roman is currently unavailable** bar. An already claimed Shopify action can finish and report its result before End chat clears the session; if its outcome cannot be confirmed, the shopper is asked to check their cart and retry End chat. Read-only views remain available. A recovered status refreshes the conversation, resumes unsent queued work and records the current storefront page visit. Voice requires an explicit Start voice after an outage in the current page; an outage does not change the customer's saved voice preference. A failed availability check retains the last confirmed status and retries; the first check must succeed before automatic voice startup. Closing Roman stops availability polling until it opens again.

## Developer tools

On `hd-dev-multi`, `hd-dev-single` and the local preview, select **Settings** (inside the hamburger menu on mobile) to choose a voice or run a tool with editable JSON arguments. Return from Settings or press Escape to return to chat; the conversation, voice connection and tool results remain mounted. The drawer calls `createAssistantTools(...).execute(name, arguments)` directly; no LLM or OpenAI key is involved in manual tool execution. The same validated functions can serve future model calls. The drawer is hidden on production stores.

| Tool                 | Arguments                                | Behavior                                                                           |
| -------------------- | ---------------------------------------- | ---------------------------------------------------------------------------------- |
| `search_products`    | `{ query }`                              | Live catalog search, up to 10 results                                              |
| `get_product`        | `{ id }`                                 | Details for a product or variant GID from search                                   |
| `lookup_catalog`     | `{ ids }`                                | Batch lookup of 1–10 product/variant GIDs; retains matches and missing-ID messages |
| `get_product_guides` | `{ productPath }`                        | Read the matching current PDP's store-linked measuring/fitting PDFs                |
| `discover_guides` | `{ library: "blinds" \| "curtains" }` | Read a fixed store library's written sections and PDF links without navigation |
| `get_store_support` | `{}` | Read the current footer's phone, hours and contact link when present |
| `get_cart`           | `{}`                                     | Current cart totals, line keys and Shopify's applied discount names and savings    |
| `add_to_cart`        | `{}`                                     | Submit the configured current PDP through its theme form                           |
| `add_sample_to_cart` | `{ productPath? }` | Use the current PDP?s separate sample control; never submit the full blind |
| `get_product_configuration` | `{ productPath? }` | Read current units, dimensions and supported native product choices |
| `configure_product` | `{ productPath?, configurationId, controlId, optionId }` | Apply one available choice from a fresh configuration read |
| `remove_from_cart`   | `{ lineKey }`                            | Invoke the theme's removal control for that line                                   |
| `set_cart_quantity`  | `{ lineKey, quantity }`                  | Set a positive whole-number quantity through the theme                             |
| `clear_cart`         | `{}`                                     | Empty the cart through the theme                                                   |
| `set_measurements`   | `{ width, height, unit, kind?, mount? }` | Save a product-specific draft; units `mm`, `cm` or `in`                            |
| `get_measurements`   | `{}`                                     | Read the current product's draft                                                   |
| `navigate`           | `{ path }`                               | Any same-origin HTTP(S) path, with full-page fallback                              |

Catalog tools call Shopify's [UCP Catalog MCP](https://shopify.dev/docs/agents/catalog/storefront-catalog) at `/api/ucp/mcp`. The embed supplies Roman's public `roman-agent-profile.json` asset; publish the extension before testing profile negotiation. The existing profile supports `lookup_catalog`. These calls need no Admin API credentials. Catalog prices are not a measured-product quote.

`src/tools/guide-library.ts` reads only `/pages/measuring-blinds` or `/pages/measuring-curtains`, with a ten-second deadline and 1 MiB HTML limit. Detached template parsing does not execute scripts, upgrade theme elements or load diagrams. Ordered sections and validated PDF links stay under a 120 KiB UTF-8 result budget; diagrams/videos carry an explicit interpretation caveat. The backend owns optional PDF reading and a 30-minute, 16-entry / 32 MiB library cache; ordinary follow-ups do not eagerly resend files. Repeated `discover_guides` calls recall cached written sections only when requested, without fetching the page or renewing the original TTL. Recall preserves source/product binding, and cancelling new work retains evidence from earlier completed turns. `src/tools/store-support.ts` prefers the dedicated footer contact block, with a bounded semantic contact fallback for other themes. Missing details stay unknown. The same footer reader verifies external contact links in chat: only its exact current contact URL opens in a separate tab, preserving voice; other external page links remain inert. Roman can offer those contact details, but cannot transfer to a human or create a Zendesk conversation.

`src/chat/ProductCarousel.tsx` owns horizontal product scrolling. Overflowing edges show an ivory fade and labelled direction buttons; the cues follow scrolling, resizing and content changes. Mouse dragging works across cards and images after a movement threshold, suppressing only the drag's click. Ordinary clicks, modified clicks and keyboard links retain navigation, and touch scrolling stays native. Pointer state and observers are cleaned up with the carousel. No carousel library is required.

Carousel images prefer the first image in the theme's main PDP gallery, because UCP's listing image can be a swatch. `src/tools/product-image.ts` reads the shared HD gallery hook from the current page or a same-origin, inert HTML fetch; it never executes the fetched theme. Cards keep a mid-grey image placeholder until the main photo loads, using the catalog image only as a settled fallback rather than flashing it before the main image. All cards in a nearby carousel preload without waiting for horizontal scrolling; a two-lookup admission window per carousel keeps optional image work bounded. A fresh carousel can preload visibly during text reveal, while hidden Chat, a closed assistant or a hidden browser tab cancels optional reads. Existing Shopify CDN width parameters are capped at 480 pixels for these cards. Image work yields to both model tools and catalog card reads and cancels when hidden/removed. Cards and the active gallery share one bounded 60-product, 60-second metadata cache, so requesting another image size does not refetch the PDP. Configuration-specific feature images remain in the active panel's live snapshot rather than that path-only cache. The reader validates the selected product, reconciles responsive gallery copies and bounds galleries to 24 product images. A missing or unavailable gallery keeps the catalog image.

Product cards use the returned Shopify `handle` to build `/products/<handle>` on the current storefront. When no handle is supplied, a validated same-store product URL is required. Catalog canonical domains never redirect cards to another store.

If chat rejects a successful catalog response, check the browser console for `[Roman] Catalog response rejected.`. It identifies the tool and failing product field without dumping the response. The backend's `/api/conversations/` requests synchronize pending replies, voice captions and tool execution with bounded polling; polling stops when neither a reply nor voice is active.

Cart reads use the visitor's locale-aware Ajax cart, accepting JSON served with a JavaScript content type. Cart changes invoke the theme's existing controls and methods, preserving linked insurance/warranty/dispatch rules, cart displays and saved-cart behavior. A confirmed add returns `addedProduct` with its `productPath`, `title` and optional submitted `measurements: {width, height, unit}`; units are `mm`, `cm` or `in`, and `height` is displayed as drop. Roman reports success and records the cart notification only after the theme confirms `added`. Copy `lineKey` from a fresh `get_cart` result; refresh it after changes because Shopify can change keys. If the required controls are absent, the action returns `needs_cart_page`: navigate to `/cart`, then retry. A `handed_off` result means submission was attempted but completion was not confirmed; inspect the cart before retrying. Roman does not replay mutations automatically. [Cart MCP](https://shopify.dev/docs/agents/carts-and-checkout/cart-mcp) replaces full cart state and is not the transport for this existing theme basket.

Measurement drafts persist through reloads and backend restarts with their conversation. `kind` distinguishes `window` notes (the manual default) from `order` values confirmed for entry into the chosen product inputs; `mount` is `recess`, `exact` or `unknown`. Saving preserves the exact values and units without conversion or deductions. For a configure request, Roman reads back the width, drop and units once, then saves and applies them after the customer confirms and a product is chosen. A save-only request leaves the form unchanged. `apply_measurements({productPath})` selects the confirmed mm/cm/in unit and fills the matching PDP?s active width/drop controls; supported inch fractions remain exact, never rounded. It adds no second confirmation or mounting questionnaire. Price-pending or incomplete-configuration markers do not prevent editing enabled fields; actual in-flight actions remain protected. It runs the exact theme-owned Continue customizing / price control when required and waits for pricing to settle before returning, without choosing fitting or adding to cart by itself. Unsupported controls stay manual.

`src/tools/product-configuration.ts` exposes the theme?s native feature radios, selects and checkboxes through short-lived, single-use IDs. Native nested controls carry their parent option IDs from the same snapshot; every selected and available ancestor must permit a child. A fresh read after each change discovers newly revealed choices at any supported depth. Roman resolves these from context or a suitable default, asking one quick follow-up when a meaningful preference remains unknown. Changed pages, controls or selections invalidate the capability. Settled, visible native price labels supply the current `configuredPrice` and each verified option surcharge as `priceLabel`; unknown or ambiguous prices are omitted, never calculated from catalog data. Option charges appear in relevant choice questions and the product total appears briefly in the final review. `src/tools/product-measurement-guarantee.ts` owns the separate native product-level guarantee: it reads the visible title, terms, yes/no choices and surcharge, validates the component and pricing owners, and uses their native click behavior after an explicit customer choice. Its fee remains separate from `configuredPrice`. Fresh capability checks and post-click readback prevent stale or unconfirmed changes from being replayed. Locked/hidden choices, unsupported custom widgets, cart-level insurance, non-feature accessories and purchase controls are not force-enabled. `src/tools/product-sample.ts` validates the separate initialized sample component and waits for its own cart confirmation. An existing sample returns `already_in_cart`; a confirmed sample gets a distinct timeline event and never appears as a full-product addition. Both outcomes continue with relevant quick next actions, without interrupting a sample request with the product guarantee offer.

Live Shopify calls require the installed storefront and its browser session; localhost reports that limitation instead of returning sample data. Tool runs are explicit, single-flight and bounded; removing Roman cancels its pending observations/requests; saved drafts remain with the server conversation. Cancellation cannot undo a cart change already handed to the theme. Manual tool results exclude cart tokens, notes and customer attributes; public catalog/cart responses stay in the drawer. Measurement reads/writes use the authenticated backend and lazily start a conversation. Model cart outcomes are minimized and persisted so later text or voice turns know whether an action completed, was declined or needs verification.

Historical product cards hydrate only near the visible transcript and cancel obsolete display reads. Carousel image space stays neutral until the main PDP photo has loaded; catalogue imagery is used only when that photo is unavailable, avoiding a swatch-to-photo flash. The storefront executor batches overlapping lookups, keeps one physical request active, and reserves priority for current conversation tools. Display work cannot fill the foreground tool queue. Theme error observation is scoped to asset loading and synchronous page activation, including custom-element constructors and connection callbacks; unrelated or later errors do not keep a global listener alive.

Shopify's cart discount evidence is shared by the model and cart display: original prices, final prices, named line allocations and separate cart-wide allocations. Missing metadata stays unknown. Final cart totals already include those savings; allocations are explanatory and are never subtracted again. This reads applied offers only, without additional Admin API permissions or a store-wide promotion feed.

## Design and fonts

The light [Fixed assistant - Empty session](https://www.figma.com/design/MHKvB5SNK2Z81DKYBSFbYt/Shopify-%7C-Roman-AI?node-id=27-200) defines ivory `#F7F5EF`, burgundy `#4E0E0E` and the outlined logo. The loading state uses the same light palette. Keep the exact Figma assets in `src/assets/`; the build copies the logo and texture into the extension and inlines the small close icon in the launcher.

Use the theme's **`GelicaSite`** font family, with Georgia as fallback. Gelica is confirmed working on the development storefront. SelectBlinds preloads normal and italic Gelica; the UK and Ireland themes declare Gelica but currently preload Inter instead. Themes own font loading in production. The local preview declares Gelica using SelectBlinds' public font URLs only for visual development. Those files are static Regular and Italic fonts: declare each as `font-weight: 400`, not `400 700`. Declaring the regular face as supporting 700 makes bold use the same regular glyphs. Themes should declare a genuine bold file at 700 if available; otherwise the corrected regular declaration allows browser-synthesized bold. Roman styles `strong` at 700 and permits weight synthesis.

The theme registry selects hooks by permanent Shopify shop identity. Development stores reuse production theme hooks where behavior matches. Customer-clicked and developer-tool navigation accepts any same-storefront path; there are no configured store route lists. Model navigation uses the public-page policy in root `shared/navigation-tool.ts`: Home, the underlying cart page when needed for native actions, products, collections, search, pages, policies and blogs, with explicit read-only query parameters. Cart actions/permalinks, account, checkout, app/API endpoints and ambiguous encodings are rejected before requesting them. Unknown stores remain unconfigured. Local demo pages belong to `vite.config.ts`, and representative navigation test routes belong to test fixtures.

Keep integration requirements and investigation findings in the owning theme README. Share navigation and history behavior rather than copying it into theme folders. Discover assets from the current theme; do not pin generated theme IDs or asset hashes in application code.

Customer-clicked and developer-tool navigation failures log `[Roman] Storefront navigation failed; loading the full page.` and hand the validated destination to the browser. This covers fetch errors, incompatible page layouts, unsafe scripts, component conflicts and initialization failures. Back/Forward keeps the selected history entry; failures after a history push reload that entry without duplicating it. Cancelled or superseded requests do not trigger this fallback. Enable **Preserve log** in DevTools to retain the reason across refreshes; diagnostic URLs omit query strings and fragments. Roman restores its saved visibility and transcript after a full page load; voice can reconnect on opening unless the customer has opted out for this tab. Do not replay arbitrary inline scripts or hide conflicting custom-element registrations; evaluated scripts cannot be rolled back.

Model page fetches reject redirects and never fall back to an automatic full-page load. If a theme needs native navigation, Roman explains the limitation so the customer can return to the store; product prose links cannot bypass selection confirmation. This prevents a public page redirect from bypassing the cart tool boundary.

The optional [PayPal handler](src/navigation/shared/paypal.ts) is shared by every store. If a destination includes the supported SDK tag, Roman validates its configuration, loads it once per document and waits for readiness before connecting the new product. Pages without the tag do no PayPal work. An existing SDK survives page replacement; incompatible configurations and SDK failures still require a reload. The theme and PayPal own message rendering and checkout controls.

Ordinary script and stylesheet load failures or 15-second asset timeouts emit `[Roman]` console warnings and allow navigation after the remaining assets settle. There are no filename-specific skips; warnings include the asset origin/path without query parameters. Unsafe markup, unsupported integrations, other script runtime errors and required payment-component readiness failures stop in-place navigation and trigger the full-page fallback. Cancellation stays silent. A successful page swap does not guarantee every theme feature works.

When generic script validation fails, expand `[Roman] Unsafe storefront scripts blocked navigation.` in the browser console. Its `blocked` list identifies each rejected script or inline attribute by reason, script source/type and a structural selector in the fetched page. The report includes the destination and theme; it omits URL credentials, query strings, fragments, inline code and attribute values. The existing page stays intact until the browser takes over. Theme-specific SDK and cart checks can fail earlier with their own errors.

## Verification

Run `npm run check` for the complete checks. For extension changes, rebuild the frontend and run `shopify app build` to include Theme Check. Tests use DOM fixtures and a simulated payment SDK; they do not prove live pricing, payments, analytics or voice continuity.

On each target theme, test a cold first open, cached reopen, closing while loading, full page navigation/reload while open and closed, arbitrary product/collection/search paths, Back/Forward, rapid navigation and request failures. Compare product options, measurements, pricing, galleries and cart behavior with normal navigation. Check keyboard focus, a 1280px desktop, a wider desktop and the mobile overlay; theme breakpoints still follow the full viewport.

Tailwind utilities that depend on `@property` need verification inside Shadow DOM, especially shadows, rings and transforms. The launcher uses explicit border/outline and box-shadow values.

The [theme extension](../extensions/vx-roman-ai-assistant) owns Liquid and translations. Shopify loads `roman-assistant-loader.bundle.js`; that shell requests `roman-assistant.bundle.js` on first open or restored visibility. Both bundles and the copied logo/texture are generated and excluded from Git. Rebuild before publishing; never edit generated assets by hand.

Conversation polls send durable and active-text versions; unchanged responses omit history. Healthy reads perform no recovery writes, and historical Markdown is memoized. Deploy backend changes before the frontend when changing the read contract.
